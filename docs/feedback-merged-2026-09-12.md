### 1-B. 기문둔갑 — 지반 `乙` 영구 누락

`qimen/index.ts:166-176`: `SANQI_LIUYI` 9개 중 `i < 8`로 8개만 배치, 중궁(5)은 기궁 간을 복제.

- 양둔·음둔 × 1~9국 18개 지반 전부 `乙` 없음 (B 실행 확인)
- 천반도 지반 값으로만 만들어지므로 `乙` 관련 격 조건(용둔 `乙+戊`, 풍둔 `乙+丙`, 호둔 `辛+乙`)은 dead condition (`qimen/index.ts:411-422`)
- 시간 간이 `乙`이면 `findPalaceOfStem`이 5 반환 → `resolveCenter`로 양둔2/음둔8에 **확정적** 오배치 (`:233-239, 504-508`)
- `determineYuan`은 `간략화: 경과일 / 5` (`:190-204`)
- **주의**: `i < 9`로만 바꾸면 9번째 간이 시작 궁의 戊를 덮어씀 → 중궁 포함 배치 모델부터 재정의 필요 (B 지적, 정확)

### 1-C. 격국 — 화격·종격 도달 불가

`saju/gyeokguk.ts:306-347`: Step 2(정격)가 유효 팔자에서 **항상** 반환.

- 월지 지장간은 12지지 전체 존재(`sipsin.ts:16-28`), `determineSipsin`은 유효 간 조합에 항상 10십신 중 하나 반환, 10개 전부 `GYEOKGUK_INFO`에 존재
- 따라서 정상 입력에서 `detectHwagyeok`/`detectJongyeok`/`OEGYEOK_DEFAULT`는 도달 불가. A의 "거의 항상"보다 강함 — B도 동일 판정("확정 결함")
- B의 추가 지적: 진입 경로를 복구해도 `detectHwagyeok`의 성립 조건(간합+월지 오행 득령 정도) 자체가 문헌 검증 필요

### 1-D. 절기 경계 — 기문과 대육임이 **반대 방향**으로 틀림

공통 `SolarTermInfo`가 `hour/minute/second`를 보유하고 timestamp 조회 API(`getSolarTermOnOrBeforeDateTime`)도 있으나 두 모듈이 미사용.

| 모듈 | 메커니즘 | 오류 방향 | 재현 |
|------|----------|-----------|------|
| 기문 | `getSolarTermOnOrBefore(solarDate)`: 절기의 **분수 포함 julianDay** vs 입력일 00:00 UTC의 JD 비교 (`solar-terms.ts:219-229`) | 새 절기가 **약 1일 늦게** 적용 | 하지 2024-06-21 05:51 KST 절입인데 6/21 하루 종일 망종/양둔, 6/22 00시부터 하지/음둔. 둔 구분까지 바뀌는 결함 |
| 대육임 | `new Date(term.y, m-1, d)`로 시각 절삭 후 비교 (`daeyukim/index.ts:438`) | 새 월장이 **절입 전 자정부터** 조기 적용 | 우수 2024-02-19 13:13 절입인데 00:00부터 월장 亥 반환(정상은 대한~우수 구간 子) |

A는 둘을 "date-only"로 묶었으나 B가 오류 방향이 반대임을 정확히 짚음. 기문은 분수 JD 때문에 단순 date-only보다 더 나쁨(당일 전체가 아니라 다음날부터 적용).

### 1-E. 궁합 — 시간미상 시 오행보완 점수 편향

`compatibility/scoring.ts:137-157`: `ideal = 16/5` 고정. 시간미상이면 실제 유효 글자 12~14개인데 이상 분포는 16글자 기준 3.2 고정 → 체계적 왜곡. B 재현: 현행 17점 vs 유효 글자 분모 적용 시 19점. 편향 방향이 모든 입력에서 같다고 단정은 불가.

### 1-F. 매화역수 — modulo + 입력 손실

- `modWithFloor`(`maehwa/index.ts:182-185`)가 음수 비정규화 → `divineByNumber(-1,·)`은 `TRIGRAMS[-1]`=undefined → `ENGINE_EXECUTION_ERROR` (B 실행 확인)
- **B 추가 발견**: `NaN`/`Infinity`/`null` 입력이 `cloneJson`(JSON 왕복)에서 `null`로 수렴 → `null % 8 = 0` → 상괘 8(곤)로 **정상 괘를 조용히 반환**. 세 입력이 동일 inputHash를 가짐. 에러가 아니라 잘못된 정상 결과라 더 나쁨
- 계약 검증은 `method` 문자열만 확인 (`validate.ts:96-100`)

### 1-G. 계약 검증 부족 — 단, 하위 방어 존재

`validate.ts`는 대부분 "객체인가/정수인가" 수준. 그러나 B의 교정이 맞음:

- `hour: 24`는 계약 통과하지만 `timestampFromUtcParts`의 UTC 왕복 검사(`temporal.ts:22-51`)가 `ManseryeokRangeError` → `OUT_OF_RANGE`로 차단 (자미·기문·대육임 모두 getGanji/getSolarContext 경유)
- **실제로 성공하는 잘못된 입력**: 하락 `2024-99-99`(정수만 확인), 홍연·대정 `{palja:{}}`(빈 객체 → `?? 0` 합산으로 정상 괘), 매화 음수/소수/null, 사주 `birth` 내부 필드, 잘못된 gender
- 즉 "검증 부족"과 "잘못된 결과 반환"을 구분해야 함: hour 범위는 차단되나, 위 목록은 실제로 통과

## 3. 유지보수/설계 사항 (버그 아님)

- **`normalizedInput`은 단순 `cloneJson`** (`execute.ts:134`): 기본값 생략/명시에 따라 hash가 달라짐. 단 `stableStringify`가 키 정렬을 하므로 키 순서 차이는 무시됨. 입력 식별용이면 현재도 유효, 계산 의미 식별용이면 canonical 기본값 처리 필요
- **버전 이원화**: package `0.1.0` vs `ENGINE_VERSION 0.3.0` — 독립 버전 자체는 허용되나 버전별 책임·변경 규칙 문서화 필요

- **`@TEST` 주석의 테스트 경로가 현재 트리에 없음**

## 5. 통합 수정 순서

피드백 A·B의 순서를 병합한 안:

1. **자미두수 묶음 수정** — ① 오행국을 명궁 간지 납음으로(기존 `getPalaceStems`+`NAYIN_JU_MAP` 재사용 가능) ② `NAYIN_JU_MAP[8,9]` → 4 ③ 子·丑 궁간 `(i-2+12)%12` 거리 수정 ④ 12궁명 역행 수정 ⑤ 자미성 기궁 공식을 참조 구현 기준으로 재작성. **검증**: 국수×일 150개 fixture와 실제 명반(궁간·궁명·14주성·대한) fixture 분리, 참조 구현(iztro) 버전 고정
2. **기문 지반 모델 재정의** — 9간 보존 + 중궁 기궁 정책 명시. 지반·천반·시간 간 탐색과 `乙` 관련 격 도달성 테스트
3. **격국 진입 경로 복구** — 특수격 우선 평가 등 precedence 정책 결정 + `detectHwagyeok`/`detectJongyeok` 성립 조건 자체의 문헌 검증(순서 교환만으로는 미완)
4. **기문·대육임을 공통 시각 context로 통합** — `getSolarTermOnOrBeforeDateTime` 계열 timestamp 조회 사용. 기문 24절기/대육임 12중기 선택 규칙은 유지
5. **계약 검증 강화** — 비유한수·null·음수·잘못된 enum·빈 팔자·불가능 날짜·hour 0~23·gender enum·음력 윤달을 실행 전 차단. 시간미상 허용 여부 모듈별 정책 결정
6. **잔여 정리** — `jijangganSipsin` 복원 또는 함수 제거, 궁합 유효 글자 분모, 매화 정규화 modulo, 홍연·대정 `PARTIAL_THREE_PILLARS` 경고, 작명 부분 한자 정책, 토정·구성·하락·대육임 간략 산법의 채택 근거 문서화
7. **후속** — 버전 체계 문서화, export manifest 일원화, 달력 `12신살` 용어 정리

- **수정 전 experimental 처리**: 자미두수(5건), 기문둔갑(지반+절기), 격국(특수격 미작동 — 사주 모듈에 영향)
- **정책 결정 필요**: 토정(생년·압축), 구성(간략 공식), 대육임(간략 과명), 홍연·대정(3주), 작명(부분 한자)
- **품질 점수는 부여하지 않음** — 측정 근거 없는 평가이며, 위 검증 범위와 결함 목록이 판단 근거로 적절 (B의 교정 수용)
