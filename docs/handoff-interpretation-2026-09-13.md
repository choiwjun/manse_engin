# 핸드오프 — 해석 계층 로드맵 (2026-09-13, 계량기 2차 반영)

> 이 문서는 `feat: 해석 계층 1차 구현`(44fe6fc)과 2차 강약 계량기 커밋의 다음 단계를 인수인계한다.
> 세션 컨텍스트 없이 이 문서 + 코드만으로 작업을 이어갈 수 있게 쓴다.

## 0. 프로젝트 비전과 제품 정의 (가장 중요)

- 엔진 13모듈(사주·자미·기문·육임·매화·토정·작명·궁합 등)은 계산 완성. 남은 것은 **풀이 수준을 "상담 등급"으로 끌어올리는 것**.
- 목표: 사주 상담을 직업으로 하는 사람이 요청을 받고 만세력 펼쳐놓고 하나하나 조합해 내주는 **그 수준의 풀이 문서를 엔진이 통째로 생성**.
- 상담사가 지갑을 여는 것은 해석 문구 자체가 아니라 **① 상담 준비 시간 절약 ② 고객에게 파는 리포트 산출물(추가 매출원) ③ 계약·학파 실수 방지 안전망**. 해석 텍스트는 제품을 "전문성 수준"으로 보이게 하는 재료.
- 사업 구조: 전문가용 "만세력 도우미" — 일회성 라이선스(19~29만, 활성화 서버) + 연 갱신(5~9만, 세운·문구 DB 확장). 해석 문구 제작은 콘텐츠(블로그/쇼츠/스레드)로 병행해 사전마케팅 겸용(사전예약 수집이 진짜 KPI).

## 1. 완료 상태

### 1차 (44fe6fc): detector·조립기 골격

- `src/engine/interpretation/` — 기존 계산 코드 미수정, `SajuResult`만 소비하는 순수 함수 레이어.
  - `types.ts` / `registry.ts` / `sipsin-groups.ts`(십신 묶음 헬퍼)
  - detector 15종(흐름 4·과부족 5·관계 2·교차 3·시점 1), 조립기 `interpretSaju()`
- 품질 규칙: 조합키 = content DB ID(`saju/{category}/{pattern}`, 한글 신살명은 한글 그대로 — 로마자 혼용 금지, 실제 버그 났던 지점), 미등록 키 게이트, evidence 필수, 강도 0~1.
- 환경 노트: `packages/myeong-engine` esbuild 플랫폼 불일치 시 `npm ci`. `buildSajuResult`의 `now`는 Date 객체, 봉투 API는 ISO 문자열. 새 export는 **루트 `src/engine/index.ts`와 패키지 `src/index.ts` 둘 다**에 추가.

### 2차 (이번 커밋): 강약 계량기 — 전문가의 첫 판단을 수치화

- `meter.ts` — `measureOhaeng(SajuResult) → OhaengMeter`:
  - **가중치 체계(고정, 회귀 테스트로 잠김)**: 천간 슬롯 1.0 / 지지는 지장간 개수별 분해 — 단기지지 1.0, 2종 [0.7, 0.3], 3종 [0.6, 0.3, 0.1] (본기→여기 순) / **월지 ×2**(월령 앵커).
  - 출력: 오행 5개 점유율%(소수 1자리), 일간 축(비겁+인성) 점유율과 판정, 월지 계절·왕오행.
  - **판정 임계값**: 신강 ≥ 55% / 신약 ≤ 42% / 중화 사이. (1985-01-10 명식 골든: 토 25.6%·수 32.2%·금 20%·목 11.1%·화 11.1%, 합 9.0, 일간 36.7% 신약)
  - **계절 키는 한자**(`丑`, `寅`…) — 팔자의 `monthJi`가 한자라서. 한글 키로 쓰면 조용히 빈 값이 된다(실제 겪은 버그).
- detector 4종 추가(`detectors/strength.ts`): 신강(중립)·신약(주의)·오행 편중(격차 15%p 이상, 주의)·결오행(중립). → 총 **19종 detector, 레지스트리 40키**.
- 조립기 헤드라인에 수치 반영: `비견격 · 일간 신약(身弱) 36.7% · 용신 금 — …`. `SajuInterpretation.meter`로 계량 결과 전체 노출.
- 공개 API 추가: `measureOhaeng`, 타입 `OhaengMeter`·`OhaengMeterSlot`.
- 테스트: `interpretation.test.mjs`에 계량 골든 값(9.0 총점 분포·신약 36.7%) 잠김 — 가중치 변경 시 여기서 깨진다. (교훈: 골든 값은 코드에서 읽어 쓰고 손계산 금지 — 시간 壬 누락으로 한 번 틀렸었다.)

## 2. 다음 단계 — "상담 등급" 경로 (우선순위 순)

### 1) 동적 문장 생성기 (최대 변곡점)

- 레지스트리 문구를 "고정 1문장"에서 **"위치·강약·용신 파라미터를 받는 템플릿+슬롯"**으로 전환.
- 목표 예시: "일지에 앉은 식신 酉이 시간의 정재 壬을 생하여(식상생재, 강도 최상), 몸에 밴 기술이 말년으로 갈수록 실속이 됩니다."
- 구현 방향: `DetectedPattern`에 슬롯 데이터(대상 기둥·글자·십신·강도 백분율)를 추가하고, registry의 `defaultText`를 문장 조각(첫형·연결형·결론형)으로 분해해 강도/위치에 따라 조립.

### 2) 축별 조립 — 상담 문서의 목차

- 연애(배우자궁=일지·배우자성), 재물(재성의 질·양·축재 방식), 적성(십신 구조), 건강(오행 밸런스·결오행), 육친(부모·형제·자녀 별) 섹션 생성.
- `interpretSaju(result, { context })` 확장 또는 `assembleReport(result) → { sections: {...} }`.

### 3) 시점 서사

- 대운×세운×월운 결합 문장: "2028년 무신 대운 진입 + 식상 유리 — 전환 구간".
- **역검증 포인트**: 과거 대운 구간에서 감지 패턴이 예측하는 사건 유형을 "확인 질문"으로 표기 (상담사의 실전 기술을 시스템화).

### 4) 문구 DB + 콘텐츠 파이프라인 (1~3 위에서 병행 가능)

- `content/entries/{module}/{combo-key}.yaml` — 조합키는 패턴 레지스트리와 동일 ID. 스키마: `id, title, audience, status(draft→linted→reviewed→published), evidence(sampleBirth+assert), body{short,medium,long}, tags`.
- CI `content:validate`: sampleBirth로 엔진 재실행해 assert 대조 + 금칙어 린트(반드시/보장/실존인물).
- 문구 생산: LLM 초안(엔진 facts 바인딩) → 사람 검수 → `reviewed`. 조립기가 DB 문구 있으면 `defaultText` 대신 사용(오버라이드 1줄).
- 콘텐츠 채널: 블로그(긴 문구, Tistory 자동+네이버 수동) / 쇼츠(Remotion+TTS, YouTube API 하루 ~6개) / 스레드·인스타(자동 발행). 시리즈: 십신 40 → 신살 20 → 격국 → 궁합 → 작명. 랜딩은 역할 필드(상담사/학습자/일반) — 예약자 중 상담사 비율이 KPI.

### 5) detector 확장 (병행)

- 조후(계절×일간 — 계량기의 `season`을 재료로 사용), 원진(`analyzeWonjin` 재사용), 삼합/방합 세분, 종격·특수격 분기, 대운×세운 이중 교차.
- 추가 절차: registry에 키+문구 → detector 작성 → `DETECTORS` 배열 → 테스트 골든/부정 케이스.

### 6) 제품·사업 (콘텐츠 검증 후)

- 워크스테이션: 고객 DB·원클릭 브리핑·시간 미상 안전 모드(야자/조자 비교·진태양시)·다인 비교·상담사 브랜드 리포트.
- MVP 권: 사주+궁합+작명+택일 4권. 사전판매(역학 카페·학원, 100명)로 시장 검증 후 본 개발.
