# 토정비결·작명 확장 명세

상태: 사용자 범위 승인(2026-10-06). 선택 질문에 응답 없어 안내한 권장 기본값 적용: 미검증 해설 숨김, 윤달 평달 환산(호출자가 reject 선택 가능). 기존 제품기획서의 변경 부록.

## 목적·현황·범위
고객별 토정비결과 사주 용신에 맞는 이름 후보를 상담사에게 제공한다. 기존 토정 계산/144괘 문구와 작명 2,137자/81수리 계산은 존재한다. 원격·형격이 뒤바뀌고 획수 출처가 없으며 미등록 한자에 한글 획수를 섞는 문제가 있다.

- T1: 토정 입력의 양/음력·윤달·대상 연도를 명시하고 산출 근거를 반환한다. 해설의 원문 대응은 검증 상태로 관리한다.
- N1: 출처·버전 고정 획수 DB, 원형이정 산식 교정, 미등록 한자 거부, 계산 기준 표시.
- N2: 사주의 선택 용신을 이용한 제한된 이름 후보 생성·순위·추천 이유. 의미/독음/자원오행과 획수의 출처 상태를 분리한다.
- W1: 기존 고객 상세에서 실행하고 고객별 스냅샷 보존, 결과·경고 표시. 공개 발행·배포는 범위 밖이다.

## 사용자 흐름·정보 구조
고객 상세 → 토정비결(대상 연도·윤달 정책) 또는 작명(성·한자 성·획수 기준·희망 이름 선택) → 입력 검증 → 고객 출생정보로 계산 → 스냅샷 저장 → 같은 화면의 결과/근거 확인. 오류는 이유와 수정 방법을 보여주고 재입력을 허용한다. 빈 후보는 제한된 후보군임을 설명한다.

## 화면·디자인·접근성
기존 회색/흰색 카드, 한글 본문, 고객 상세의 수직 구성 유지. 입력→기준→결과→상세 근거 순서. 두 기능은 독립 form/fieldset, label과 id 연결, 필수 표기, native select/button, 키보드 포커스, 작은 화면에서 세로 배치 및 표 가로 스크롤. 신뢰 상태는 색 외 텍스트로 표시. 요청은 서버 렌더링이며 오류 페이지에 돌아가기 제공. 삭제 고객은 실행 불가. 브라우저에서 입력/결과/오류·좁은 화면 확인.

## 기술·API·데이터
엔진은 순수 TypeScript, 앱은 기존 서버 렌더링 Node 서버. tojeong 계약에 calendarType/isLeapMonth/leapMonthPolicy를 추가하고 계산 근거와 해설 상태를 반환한다. 기존 생년월일+대상 연도 API의 음력 기본값 유지.
작명은 기존 naming 모듈에 추천 모드를 추가해 envelope의 입력/버전/hash에 추천 조건과 출생정보를 보존한다. 직접 추천 API도 export한다. 추천은 검토용 후보이며 이름의 효과나 신고 적합성을 보증하지 않는다. 기존 수리 길흉표는 프로젝트 단일 정책으로 명시한다.
획수는 Unicode 원자료의 버전·해시와 추출값을 저장하고 재생성 스크립트 제공. 한국 인명용 한자 최신 법적 허용 여부를 Unicode 등재로 추정하지 않는다. 자원오행은 기존 프로젝트 분류로 표시한다.

## 저장·보안
기존 immutable calculation_snapshot envelope로 저장하며 별도 DB 테이블/마이그레이션 없음. 입력/결과는 기존 고객 정보 삭제·보존 정책을 따름. 서버에서 고객을 조회하고 고객 출생정보를 사용. 인증 경로·workspace 검증 유지, HTML escape, 입력 길이·후보 수 상한, 오프라인 계산. 외부 문헌 조회에 개인정보 전송 없음.

## 작업·인수 기준
T1: 잘못된 날짜/미래 생년 거부, 양음력 동등성, 윤달 정책 명시, 29/30일 경계, 실제 괘 예제, 144 조합 및 해설 검증 상태.
N1: 花/海/朴/萬 등의 독립 사전 예제, 2,137자 출처 커버리지, 강희/현대 차이, 원형이정과 외자 경계, 한자 누락/불일치 오류.
N2: 용신 변화에 따른 후보/이유 변화, 같은 조건 결정성, 후보 제한/희망 이름 필터, 근거·획수 기준 표시.
W1: 인증된 고객별 실행/스냅샷, 잘못된 입력 오류, 삭제 고객 차단, HTML 이스케이프, 기존 사주·상담 리포트 회귀 없음.

## 구현 규칙·완료 조건
기존 TypeScript 및 서버 HTML 규칙 유지. 엔진 소스는 src/engine만 수정. 버전 변경으로 이전 결과와 구분. 공개 API 회귀 테스트부터 재현하고 수정, 패키지 전체 테스트 및 워크스페이스 QA 실행. 결과/미검증 부분/실행 증거를 run 기록에 남긴다.

## 데이터 검증 결과·채택 기준

- 기존 한자 2,137자 모두 Unicode 13.0.0 kRSKangXi와 Unicode 17.0.0 kTotalStrokes에 대응. 강희 242건/현대 649건 교정. 원자료 SHA-256, 원래 radical.residual, radicalStrokes, 현대 대안 획수·독음 저장.
- kRSKangXi는 강희 부수+나머지 획수의 참조값(Unicode의 provisional property). 강희 부수 원획수를 더한다. kTotalStrokes는 첫 값인 G를 명시해 사용하며 한국 자형 표준으로 주장하지 않는다.
- https://www.unicode.org/reports/tr38/tr38-29.html#kRSKangXi
- https://www.unicode.org/reports/tr38/tr38-39.html#kTotalStrokes
- https://www.zdic.net/hans/花 (강희 10), https://www.zdic.net/hans/海 (강희 11): 독립 표본.
- 원격=이름 합, 형격=성+첫 이름, 이격=성+끝 이름, 정격=전체 합. 외자에는 가성수를 넣지 않는 기존 실획수 정책을 명시. 별도 fiveGrids는 단성/외자 각각 +1을 사용하는 오격이며 그 수치와 기존 사격 길흉 점수를 섞지 않는다. 산식 참조: https://patentimages.storage.googleapis.com/e1/87/a7/d9102c90f5997b/KR102502645B1.pdf
- 추천은 기존 자원오행 분류를 적용한 편집 60자 후보군. 기존 2,137자 전체가 이름으로 적합하다고 간주하지 않는다. 두 음절 기본, 희망 독음 1~2음절 필터, 최대 6개. 용신 일치 수→기존 점수→코드포인트 순서. 이름 효과의 실증 근거와 무관한 전통 규칙 기반 추천임을 명시.
- 토정 계산 체계 참조: 국립민속박물관 https://www.nfm.go.kr/_Upload/BALGANBOOK/817/sesi01.pdf 및 https://encykorea.aks.ac.kr/Article/E0059207 .
- 기존 토정 144개 항목에는 판본·원문·출처 필드가 없다. 111괘조차 기존 '건곤일척'과 공개 원문 자료 '東風解凍 枯木逢春' 대응이 다르므로 검증 완료로 승격하지 않는다. 원자료 대조가 끝나기 전 API interpretation=null/contentStatus=unverified, 앱은 계산 사실만 제공한다. 기존 파일은 미검증 보관본으로만 남긴다.
- 출생 날짜 자체는 유효한 양/음력 날짜여야 한다. 윤달 출생의 평달 대응과 대상년 소월의 30→29 보정은 문헌 공통 정답이 아닌 명시한 서비스 정책이다.

### 토정 계산 근거 대조 상세
국립민속박물관 자료 PDF 39~40쪽(책 101~102쪽)은 생년월일 기반의 상·중·하 세 자리 구조와 월별 해설의 구성을 뒷받침한다. 이 자료만으로 숫자표 전체가 검증되었다고 주장하지 않는다.

구체 수치/공식은 산법을 공개한 길라의 자체 설명과 대조했다:
- https://www.gilra.kr/fortune-lab/records/advanced.tojeong.calc1 — 공통 천간수·연월일 지지수, 태세 60갑자표, 상괘 예제.
- https://www.gilra.kr/fortune-lab/records/advanced.tojeong.calc2 — 대상 연도의 음력 생월 대소 및 월건, 6 나머지.
- https://www.gilra.kr/fortune-lab/records/advanced.tojeong.calc3 — 대상 생일 일진수, 3 나머지.

코드의 태세수(중천수 간+지)는 해당 표의 공통 천간수+태세 지지수와 같은 값이다(천간 +2, 지지 -2로 상쇄). 월건과 일진은 표 그대로 대응한다. 이는 채택한 공개 산법과의 일치 검증이며 모든 판본의 단일 정답을 선언하는 것은 아니다. 윤달·30일 말일 보정은 별도 서비스 정책으로 계속 표시한다.
